## 尺寸必須分開
1. 生成母圖高解析，供 Flow 或其他已授權工具辨識骨架與細節。
2. Runtime 每格測試 64/96/128 級同源比較；優先 128px 級角色和小型怪物，較大體型或動作占幅使用 256/512 或適當矩形格，勿強制填滿。上述是 pilot 建議非固定分級或最終數值。
3. 遊戲世界顯示大小與素材格大小獨立：共同 pixel density / native px per world unit；以角色既有世界高度與原 PMD 相對大小基準作同場比較，待使用者確認後凍結。勿將每張圖各自 fit 到同尺寸，勿因畫布增加讓怪物變大。怪物飛行/尾翼等使用來源合理 anchor；足點/影子/移動範圍分開。動作整套統一縮放，固定 local origin，空白保留；避免逐格拉伸或重心漂移。
## 製作與驗收
A. 原始 PMD reference + 新角色風格參考，先生成一張全身靜態候選，原始來源僅供結構參考，第三方來源使用權與外部傳送權另確認。
B. 並排原始/新圖/新角色，同遊戲顯示尺度檢查物種、頭身、肢體、進化 size、45度、像素密度、色彩及光影。ART 先行；母圖未鎖定不擴充大量動作。
C. 以新母圖做 Flow 單一動作試驗（優先 IDLE 或 RUN/適合物種的 WALK），可變真實幀數，依原 PMD XML 動作語意與實際可讀性，不硬套人形 8F。成功再做 ATTACK、HURT、CAST/SKILL、DODGE/物種適當、KO；其他原 PMD 動作按需求。普通攻擊不混技能 FX；FX/shadow 分層。未授權額外付費不提交，先記錄實際 job/費用/原始回傳。
D. 由同一生成結果產生多尺寸試驗，以原始素材1×、nearest 4×、GIF、實際戰鬥尺度對照選定；去背、統一網格、透明 alpha、腳點及 canvas 一致性，避免平滑抗鋸齒、單純放大冒充新畫質、同圖重複冒充動作。保留完整原始圖與來源 SHA。ART 合格後才 native Godot 4.7.2 與 gameplay QA。新規則不要求先擴充 engine。

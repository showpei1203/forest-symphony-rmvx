## 危險案例
- `#480 90-05 戰鬥核心Fixture` / `#481 90-06 AI/戰鬥邊界測試` 明確是測試相關命名，必須確認是否在正式 Runtime 啟用。
- `FSBattle.gd` 的普通攻擊 `ATK×4−DEF×2` 和單純屬性公式是**引擎初版 smoke candidate，不是 FS 效力等價**。
- 完整數值移植**不得**用從角色／職業資料推算的假值取代腳本最後生效的 HP/MP/被動/裝備計算。
- `Scene_Battle`、`Game_Battler`、`Game_Actor` 等多個 class 有 re-open 和 alias 混用。應以每個作用 class 的真正方法鏈 + source test fixtures 做校驗。

## 接下來的工程工作清單
1. 使用唯讀掃描器建立每一個 `class/module` + method + 章節 ID + alias/note + source hash 的 Machine-readable Authority Map（掃描器必須記錄 source span，而不是猜最終方法）。
2. 選原始 VX 程式可重現的 fixture：6 主角 LV/裝備、代表敵怪/Boss、正常/暴擊/閃避/狀態、OD/Break/Cover/召喚、完整 ATB 循環。
3. 實作帶有 RNG seed 的 deterministic Godot combat rules，使每一張 fixture 都能比較 HP/MP/OD/狀態/回合/tick 與事件順序。
4. MENU/BATTLE 使用原始圖檔像素、字型、圖示與座標，不接受功能正確但外觀不相符或反之。
5. 「資料解碼 PASS」與「規則還原 PASS」及「Godot 實機 PASS」三者獨立；目前後兩者仍 **NOT DONE**。
